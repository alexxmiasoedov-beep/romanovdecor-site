# solana_trench — отбор кошельков для копитрейдинга мемов на Solana

Пайплайн, который находит кошельки, торгующие мемкоины после миграции,
восстанавливает их сделки из блокчейна и проверяет не «PnL кошелька»,
а **PnL нашей копии**: фиксированная сумма, один вход на первой покупке
лидера, пропорциональный выход на каждой его продаже, исполнение по
резервам пула сразу после его сделки (мы всегда следующие в очереди).

## Запуск

```bash
cd solana_trench
pip install requests curl_cffi  # curl_cffi нужен только для GMGN
python3 run.py                  # пулы после миграции за сегодня -> кошельки -> фильтр
python3 run.py --max-pools 25 --max-wallets 40 --max-tx 500   # ограничить объём
python3 run.py --wallets-file gmgn_export.txt                  # свой список (GMGN и т.п.)
python3 run.py --gmgn           # + кандидаты из GMGN (нужны GMGN_COOKIE и GMGN_UA)
```

Нужен **архивный RPC с полной историей** (Helius: бесплатного ключа
достаточно, ~10 запросов/сек). Публичные узлы (`solana-rpc.publicnode.com`,
`api.mainnet-beta.solana.com`) хранят только ~1,7 суток истории: на них
возраст кошелька и 30-дневная история считаются неверно, поэтому они
используются лишь как быстрый узел для транзакций моложе суток.

```bash
export SOLANA_RPC_URL='https://mainnet.helius-rpc.com/?api-key=...'   # архивный, обязателен
export SOLANA_FAST_RPC_URL='https://solana-rpc.publicnode.com'        # быстрый, по умолчанию
python3 run.py --rps 50 --threads 16                                    # если тариф позволяет
```

Ключ живёт только в переменной окружения: в `passed.json` он маскируется,
в репозиторий не попадает.

Результат в `out/`:

- `wallets.csv` — все проанализированные кошельки, метрики, `pass` и
  `fail_reasons`;
- `passed.json` — прошедшие фильтр + конфиг, с которым считали;
- `positions_<wallet>.json` — позиции кошелька с результатом копии по каждой;
- `pools.json` — пулы, из которых брали кандидатов.

Разобранные транзакции кэшируются в `cache/cache.sqlite`, повторные
прогоны по тем же кошелькам почти бесплатны.

## Источники данных

| Что | Откуда | Ключ |
|---|---|---|
| Новые и активные пулы, сделки в пуле с адресами | GeckoTerminal API | нет |
| История кошелька, разбор свопов, резервы пула | Solana JSON-RPC (`getSignaturesForAddress`, `getTransaction`) | архивный RPC (Helius free) |
| Курс SOL по дням (для капы в $) | CoinGecko | нет |
| Текущая цена незакрытых позиций | DexScreener | нет |
| Рейтинг кошельков, топ трейдеров по токену | GMGN (`wf/gmgn.py`) | cookie сессии |

GMGN за Cloudflare: обычные запросы получают 403, но с TLS-отпечатком
браузера (`curl_cffi`) без логина доступны рейтинги кошельков по тегам
(винрейт, PnL, среднее удержание, распределение сделок), топ трейдеров по
токену и часть статистики кошелька. Это используется в `--gmgn` как
источник кандидатов, а поля рейтинга (`gmgn_*`) попадают в отчёт для
сверки. Лента сделок, холдинги и календарь PnL требуют cookie сессии
(`GMGN_COOKIE`, `GMGN_UA`); всё это мы восстанавливаем из блокчейна и
без GMGN, см. `positions_<wallet>.json`.

## Как устроено

1. **discover** — `/new_pools` и активные пулы PumpSwap, созданные за
   последние `pool_age_hours`, только DEX после миграции (pumpswap,
   raydium, meteora-damm-v2), ликвидность от `min_pool_liquidity_usd`.
2. **collect** — до 300 последних сделок в каждом пуле, адреса кошельков.
3. **prefilter** (дёшево, только подписи): возраст кошелька
   ≥ 15 суток, число tx в окне 30 дней, не больше `max_tx_per_day`
   (иначе бот), доля неудачных tx.
4. **history** — загрузка tx кошелька, разбор свопа по разницам балансов
   (`wf/parse_tx.py`): работает для pump.fun, PumpSwap, Raydium,
   Meteora, Jupiter-роутов без декодирования инструкций. Из той же tx
   берём резервы пула после сделки, значит знаем импакт и капу на входе.
   pump.fun-кривая: к реальным резервам добавляются виртуальные
   (30 SOL / 279,9M токенов).
5. **positions** — позиции по токену: открывается первой покупкой,
   закрывается, когда остаток ≤ 1% от максимума.
6. **simulate** — копия: `copy_size_sol` на первой покупке, продажа той
   же доли, что продал лидер, по константному произведению на резервах
   после его сделки, минус `fee_bps` и `latency_slippage_bps` на каждую
   сторону. Незакрытая позиция старше `dead_bag_days` — мешок: считается
   по текущей цене с DexScreener × `dead_bag_value_haircut`.
   Дополнительно считается PnL при удвоенном штрафе задержки.
7. **filter** — пороги из `wf/config.py`, каждый даёт свою причину отказа.
   Кошельки с одним источником пополнения (первая входящая tx) —
   один кластер, из него остаётся лучший.

## Фильтры (значения по умолчанию, `wf/config.py`)

| Фильтр | Порог | Причина в отчёте |
|---|---|---|
| Возраст кошелька | ≥ 15 суток | `wallet_too_young` |
| Транзакций в день | ≤ 300 | `too_many_tx_bot` |
| Неудачных tx | ≤ 35 % | `failed_tx_spam` |
| Закрытых позиций за 30 дней | ≥ 15 | `few_closed_positions` |
| Медиана времени в сделке | ≥ 3 с | `median_hold_too_short` |
| Доля выходов быстрее 3 с | ≤ 20 % | `too_many_fast_exits` |
| Доля входов после миграции | ≥ 70 % | `trades_pre_migration` |
| Снайп на кривой (резерв < 2 SOL) | ≤ 10 % входов | `sniper` |
| Медиана импакта входа (сумма / резерв SOL) | ≤ 2 % | `entry_too_big_for_pool` |
| Доля входов с импактом > 3 % | ≤ 20 % | `many_big_entries` |
| Медиана импакта выхода | ≤ 3 % | `exit_too_big_for_pool` |
| Покупок на позицию (усреднение) | ≤ 2 | `averaging_entries` |
| Медиана доходности копии | ≥ 3 % | `copy_median_ret_low` |
| Винрейт копии | ≥ 40 % | `copy_win_rate_low` |
| Профит-фактор копии | ≥ 1,3 | `copy_profit_factor_low` |
| PnL копии | > 0 | `copy_pnl_negative` |
| Доля прибыли от одного токена | ≤ 40 % | `profit_from_one_token` |
| Доля прибыльных недель | ≥ 50 % | `inconsistent_weeks` |
| PnL при удвоенной задержке | > 0 | `latency_sensitive` |
| Один источник пополнения | лучший из кластера | `same_funder_cluster` |

Метрики лидера (`leader_*`) выводятся рядом для сравнения, но в фильтре
не участвуют: решает только результат копии.

## Ограничения

- Штраф задержки — параметр, а не восстановленная цена следующего слота.
  Точную цену через 1–2 слота можно получить, догрузив сделки пула между
  tx лидера и следующим блоком; это следующий шаг.
- Капа в $ считается для supply 1 млрд (стандарт pump.fun); для токенов с
  другим supply число условно, на фильтр не влияет.
- Своп токен-в-токен и позиции, начатые до окна истории, пропускаются.
- На бесплатном Helius (~10 rps) полный прогон 40 кошельков × 500 tx занимает ~30–40 мин.
