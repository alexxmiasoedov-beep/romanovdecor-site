# Скринер мем-пулов Meteora DLMM и журнал сделок

Три файла:

| Файл | Что делает |
|---|---|
| `screener.py` | ищет пулы Meteora, проходящие фильтр стратегии, печатает таблицу кандидатов |
| `journal_template.csv` | шаблон журнала сделок, одна строка на позицию |
| `journal_stats.py` | считает по журналу винрейт, ожидание и разбивку по метрикам входа |
| `simulate.py` | paper-trading: открывает и закрывает виртуальные позиции по правилам стратегии, ведёт журнал |
| `journal_strategy.csv`, `journal_relaxed.csv` | журналы симуляции по строгому и ослабленному профилю |
| `sim_*.json`, `sim_*.log` | состояние и лог симуляции (перезапуск подхватывает открытые позиции) |

Нужен только Python 3.8+, без установки библиотек.

## Запуск скринера

```
python3 screener.py                  # разовый прогон, ~5–30 с
python3 screener.py --watch 300      # каждые 5 минут, Ctrl+C для выхода
python3 screener.py --all            # плюс список отсеянных с причиной
python3 screener.py --csv cand.csv   # дописывать кандидатов в CSV (история сканов)
python3 screener.py --no-rugcheck    # без проверки держателей, быстрее
python3 screener.py --help           # все флаги
```

Пороги лежат в словаре `CONFIG` в начале `screener.py`. Часть можно
переопределить флагами, например `--min-fee-tvl 2 --min-tvl 50000 --max-age 6`.

Режим `--all` полезен в первые дни: видно, кто «почти прошёл» и по какой
причине, и понятно, какой порог мешает.

## Источники данных

- Meteora: `dlmm.datapi.meteora.ag/pools`, отсортированные по объёму за
  час, три страницы по 100 пулов. Отсюда TVL, объём и комиссия за 1ч и 2ч,
  bin step, базовая комиссия, чёрный список.
- DexScreener: капитализация, возраст самой старой пары токена, число
  сделок за час по всем DEX (прокси числа активных трейдеров).
- Rugcheck: mint/freeze authority, доля топ-10 держателей (без известных
  адресов пулов), доля кошельков, помеченных как инсайдеры, флаги уровня
  danger.

Все три API публичные и без ключей. Если один из них лёг, скрипт пишет
предупреждение в stderr и пропускает этап, кандидаты с пропущенным этапом
не выдаются.

## Что скрипт НЕ проверяет

- Бандлы на старте точнее смотреть глазами в Bubblemaps по минту.
- Соцсети, нарратив, кто стоит за токеном.
- Ваш собственный размер против TVL: если вы кладёте больше 10–15% TVL
  пула, комиссия на доллар упадёт сразу после входа.

Кандидат из таблицы — это «можно смотреть», а не «надо входить».

## Правила входа и выхода (кратко)

Вход: односторонний в SOL или USDC ниже текущей цены, 10–20 бинов,
стратегия Bid-Ask. Размер 2–5% рабочего капитала, не больше 3–5 позиций
одновременно.

Выход, что раньше наступит:
1. Прошло 2–4 часа.
2. Собрано 15–25% от размера позиции комиссией.
3. Цена ушла ниже диапазона: закрыть и продать набранный токен сразу.
4. Объём за 30 минут упал вдвое к предыдущим 30 минутам.
5. Крупный держатель начал слив.

Дневной стоп: минус 10% капитала за день, до завтра не открываем.

## Журнал

`journal_template.csv` открывается в Excel, Numbers или Google Sheets. Первая
строка после заголовка — пример, удалить перед началом.

При открытии позиции заполняются все поля до `price_entry`: метрики берутся
из строки скринера на момент входа (не позже, иначе журнал ничего не
скажет о порогах). При закрытии заполняется остальное.

Ключевые поля:

| Поле | Что писать |
|---|---|
| `strategy` | bidask / spot / curve |
| `bins_below` | сколько бинов ниже цены занимает позиция |
| `deposit_usd` | стоимость депозита в долларах на момент входа |
| `exit_reason` | time / fee / price / volume / holders / manual |
| `fees_claimed_usd` | вся собранная комиссия в долларах |
| `tokens_left_sold_usd` | за сколько продали токен, который набрали, пока цена шла вниз |
| `position_withdrawn_usd` | стоимость SOL/USDC, вернувшихся из пула при закрытии |
| `gas_usd` | все транзакции по позиции: открытие, клеймы, закрытие, продажа |
| `slippage_usd` | потеря на продаже набранного токена относительно цены на экране |
| `net_pnl_usd` | можно оставить пустым, `journal_stats.py` посчитает сам |

Формула чистого результата:

```
net_pnl_usd = fees_claimed_usd + tokens_left_sold_usd + position_withdrawn_usd
              - deposit_usd - gas_usd - slippage_usd
```

Это единственное честное число. «Собрал 40 $ комиссии» само по себе
ничего не значит, если позиция при закрытии стоит на 60 $ меньше.

## Статистика по журналу

```
python3 journal_stats.py journal_strategy.csv
```

После 30–50 сделок разбивка по корзинам покажет, какие метрики на входе
реально отделяют плюс от минуса. Корзина с отрицательным средним и
достаточным числом сделок — кандидат на ужесточение порога в `CONFIG`.
Менять больше одного порога за раз не стоит, иначе непонятно, что
сработало.

## Симуляция (paper trading)

```
python3 simulate.py                      # строгий профиль, тик каждые 2 минуты, бесконечно
python3 simulate.py --profile relaxed    # ослабленные пороги, чтобы быстрее набрать сделок
python3 simulate.py --duration 180       # остановиться через 3 часа
python3 simulate.py --once               # один тик
./run_sim.sh 1440                        # поднять оба профиля в фоне на 24 часа, если не запущены
```

Каждый тик симулятор прогоняет скринер, открывает виртуальные позиции
по кандидатам (3% капитала, не больше 4 одновременно, повтор по тому же
токену не раньше чем через 6 часов), обновляет цену с DexScreener и
комиссию пула с Meteora, закрывает по правилам стратегии и пишет
закрытую сделку в `journal_<профиль>.csv` в том же формате, что шаблон.

Правила выхода в коде: цена ниже диапазона, комиссия 20% от депозита,
180 минут в позиции, объём за 30 минут упал вдвое (после 20 минут в
позиции). Дневной стоп 10%. Правило «крупный держатель начал слив» не
реализовано: без платного индексатора дёшево не отследить.

Модель позиции упрощённая: односторонний депозит, равномерно по цене на
15 бинов вниз; доля, сконвертированная в токен, зависит только от
текущей цены; комиссия = комиссия пула за тик × доля депозита в TVL,
пока цена в диапазоне. Это верхняя оценка: реальная комиссия зависит от
распределения по бинам, а MEV и задержки исполнения не учтены. Итог
симуляции нужно читать как «лучше этого не будет», а не как прогноз.

Профиль `relaxed` намеренно берёт сделки, которые строгая стратегия не
взяла бы. Его журнал показывает, от чего фильтры спасают, и даёт
статистику быстрее. Ориентироваться при принятии решений надо на
`journal_strategy.csv`.
