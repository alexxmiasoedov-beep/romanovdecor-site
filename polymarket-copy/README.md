# polymarket-copy: воронка отбора кошельков для копирования

Стратегия и её обоснование: `СТРАТЕГИЯ.md`. Пороги: `pm/config.py`.

```
pip install requests
python3 collect_wallets.py --since 24 # стадия 0: кошельки, торговавшие за сутки → data/wallets_today.json (только на диске, в git не хранится)
python3 stage1_screen.py --workers 24 # стадия 1: дешёвые отсечки → data/stage1.csv (отбракованных за 5 дней не перепроверяет)
python3 stage2_analyze.py             # стадия 2: история сделок, сегменты → data/stage2.csv, segments.csv
python3 stage3_markout.py             # стадия 3: задержка, маркаут, стакан → data/stage3.csv
python3 report.py                     # сводка → data/REPORT.md
python3 run_all.py                    # всё подряд
```

Любой скрипт принимает `--wallets 0x... 0x...` для проверки конкретных адресов.
Ответы API кэшируются в `data/cache/` (TTL 6 часов для данных по кошелькам),
эпизоды позиций каждого кошелька сохраняются в `data/wallets/<addr>.json`.

Колонки `stage2.csv`, на которые смотреть в первую очередь: `roi_copy`,
`t_stat`, `conc_p95`, `median_hold_h`, `approved_segments`, `exit_value_add`,
`size_signal`. В `stage3.csv`: `roi_delay5`, `keep_ratio5`, `skip_share`,
`markout_24h`, `slippage_median`.

## Реестр, симуляция и регулярный цикл

```
python3 db_update.py                          # результаты прогона → data/db/registry.json.gz (gzip-JSON)
python3 sim.py start --batch 2 --wallets 0x…  # поставить кошельки на бумажную симуляцию ($1 на позицию, старт $100)
python3 sim.py enroll                         # прошедшие стадию 3, кого ещё нет в симуляции → новый батч
python3 sim.py update                         # подтянуть новые сделки, резолвы, переоценку → data/db/SIM_REPORT.md
python3 sim.py review --batch 1               # через неделю: разметить positive/negative → data/db/positive.json
python3 pipeline.py --push                    # весь цикл: сбор → воронка → реестр → симуляция → коммит
```

Цикл: раз в сутки `pipeline.py --push` собирает кошельки за день, прогоняет воронку,
дописывает реестр, всех новых прошедших стадию 3 сразу ставит на симуляцию отдельным
батчем (`sim.py enroll`, номер батча = следующий, тег `auto-<дата>`) и обновляет симуляцию
всех батчей. Раз в неделю вручную: `sim.py review` по батчам, отработавшим ≥7 дней, разбор
причин, правка порогов в `pm/config.py`.

Симуляция воспроизводима из истории сделок API: состояние в `data/db/sim.json`, каждая
сделка кошелька обрабатывается один раз, вход по цене через 30 с после его сделки.

## Симуляция 2 — форвард-тест стратегий (с 07.10)

Отдельно от симуляции 1 (`sim.py`, батчи, реестр). 1592 кошелька из тестовой воронки (три фильтра владельца) с
подобранной на бэктесте стратегией каждому: сегмент, лайв/прематч, диапазон цены входа, ставка fix $1 или
пропорционально $1–4. Состояние `forward/fwd.json`, стратегии `forward/strategies.json`, отчёт `forward/FWD_REPORT.md`,
свой стор рынков. Входы и выходы по ленте сделок рынка через 30 с, правило 3 центов — как в симуляции 1.
Обновление: `python3 forward/fwd_sim.py update` дважды в день (09:40 и 21:40 UTC).
11.10 владелец оставил в симуляции только кошельки с реализованным PnL > 2 $ (131); убранные — `forward/fwd_pruned_*.json`,
обратно не возвращаются. 20.10 владелец убрал из обеих симуляций кошельки с ≥5 днями и отрицательным PnL: симуляция 1 — 91 (`data/db/sim_pruned_2026-10-20.json`, в реестре статус negative, стадия 1 их больше не проверяет), симуляция 2 — 399 (`forward/fwd_pruned_2026-10-20.json`). 22.10 добавлены две параллельные строки balthazar: `cat=Crypto & price=0.10-0.70 & dte<=7` и базовая стратегия с новым исключающим фильтром `-title=temperature` (слово в заголовке рынка), чтобы сравнить с базовой строкой. 23.10 исправлена ошибка расчёта: отменённые рынки (резолв 0,5/0,5) засчитывались как выигрыш (142 позиции, +205 $ лишних, у botmy +78); теперь выплата по резолву = цена исхода (`payout`), то же в бэктесте отбора. Добавлена комиссия Polymarket 5%·p·(1−p)·доли на покупку и продажу (`FEE_RATE`, подобрана по реальным позициям владельца; на части рынков комиссии нет — считаем везде); записанные позиции пересчитаны ретроспективно (комиссия входа; по продажам до 23.10 не восстановить). Симуляция 1 (sim.py) резолв 0,5 не закрывает и считает верно, но комиссий не моделирует. Ежедневный отбор новых (10:40 UTC): `python3 forward/daily.py --push` — `forward/screen.py`
по дневному сбору `data/wallets_today.json` (три фильтра + бэктест стратегий, бинарные отбрасываются), память проверенных
`forward/screened.json.gz` (повтор через 7 дней), прошедшие зачисляются (`fwd_sim.py enroll`), стратегии дня —
`forward/strategies_<дата>.json`. Таблица плюсовых: `forward/FWD_POSITIVE.md`.
